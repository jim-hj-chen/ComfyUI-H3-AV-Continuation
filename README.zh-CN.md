# ComfyUI-H3-AV-Continuation

## 音频双模式与可选处理开关

`H3AVAudioModes` 提供两个独立开关：**音色参考**、**音频驱动画面**，默认均关闭。画布上开启一个会立即关闭另一个；API 同时传入两个开启值时，后端会报错。把加载音频接到 `audio`，再把 `audio_mode`、`source_audio` 接到分段计划节点。两个开关都关闭时仍使用原来的联合音画生成，按需输入不会执行加载音频。

- 音色参考：计划节点只取录音前 3 秒，输出到 `speaker_reference`，再接入参考条件节点。H3 参考说话人的音色、口音和身份，按提示词生成新台词。不会重播参考录音，也不再强制把英文台词改成普通话。
- 音频驱动画面：把计划节点的 `driving_audio` 接到参考条件节点同名输入。录音编码为音频潜空间，使用 H3 原生分流噪声掩码冻结音频，只生成画面。画面及口型受固定录音驱动；嘴型精度仍取决于 H3，不能保证每个音素都准确。

驱动模式每段保留 `round(秒数 × 24)` 帧，按已提交的实际输出帧数读取连续录音，补入对应的上一段音频上下文。H3 帧网格多出的尾部只用于生成窗口，不进入成片。把 `kept_frames` 接到写入节点，才能同时裁掉这部分多余画面和音频，避免逐段错位。

录音应覆盖所有配置分段时长的总和。长度不足会在受影响段开始采样前报错，不会拉伸、循环或替换台词；超过配置总时长的尾部不会进入成片。建议先按录音中的停顿确定各段时长，再使各段画面脚本与录音对应。

`H3AVAudioOutput` 接到写入节点之前，连接模式、模型解码音频与本段驱动音频。驱动模式直接保留输入录音并跳过音频解码；写入时仍转为按帧对齐的双声道 PCM，最终只编码一次 AAC，因此保留的是输入语音内容，而非逐字节复制上传文件。

`H3AVOptionalVideoRefine`、`H3AVOptionalUpscale`、`H3AVOptionalAudioRefine` 分别控制二采、超分和 AudioRefine，默认关闭，真正跳过未选分支。原始数据接 `original`，处理结果接 `refined`。内部节点保持启用，不需要 Ctrl+B 旁路。音频驱动模式始终跳过 AudioRefine，即使误开启细化开关也不会重写录音。保留的 AudioRefine 分支仍需安装外部 [ComfyUI-H3-AudioRefine](https://github.com/Adudeguyman/ComfyUI-H3-AudioRefine)。

建议先用 `match` 参考图尺寸、关闭可选处理与分段含声预览建立速度基线。H3 原生源码说明 `max` 参考图的 token 会随每一步采样处理，可能慢数倍。AudioRefine 是可选音频修复；冻结缓存会增加 RAM/VRAM 用量，作者测试速度不能直接套到其他显卡。

FFmpeg 和 rawvideo 管道写入新增 600 秒超时及 ComfyUI 中断响应，防止输出编码无限等待。合法的大任务可通过环境变量 `H3_FFMPEG_TIMEOUT_SECONDS` 增加时限。失败会指出日志路径，已提交段会保留。这个超时不影响 GPU 采样，也不能修复 CUDA 驱动死锁。编码开始/结束日志能帮助定位耗时阶段。

原节点 ID、原输入顺序、计划节点输出 0–6 保持兼容；新增输出 7 为 `driving_audio`、8 为 `kept_frames`，新输入均追加且可选。

**H3 音画同步续写**

[English](README.md) | [简体中文](README.zh-CN.md)

用于 MiniMax H3 长视频工作流的 ComfyUI 自定义节点：分段计划、参考图编码、音画联合续写、二采音频保护、按帧去重与磁盘落盘，以及连续音轨成片合成。生成与采样由 ComfyUI 原生 H3 节点完成。

固定 24 fps；视频窗口满足 `17k+5`，计划节点接受 124–362 帧。上下文帧数也必须为 `17k+5`，默认 22 帧（约 0.917 秒）。计划时会向上对齐兼容帧数，因此实际新增时长可能超过目标时长。音画上下文可改善连续性，但无法保证模型在所有场景中的口型、声音或人物一致性。

## 安装

将本仓库克隆或解压至 `ComfyUI/custom_nodes/ComfyUI-H3-AV-Continuation/`，该目录内须直接包含 `__init__.py`。使用运行 ComfyUI 的同一个 Python 安装依赖：

```bash
python -m pip install -r custom_nodes/ComfyUI-H3-AV-Continuation/requirements.txt
```

Windows 便携版（在便携版根目录执行）：

```powershell
.\python_embeded\python.exe -m pip install -r .\ComfyUI\custom_nodes\ComfyUI-H3-AV-Continuation\requirements.txt
```

重启 ComfyUI 并刷新浏览器。需要 FFmpeg 支持 `libx264` 与 `aac`；优先使用 PATH 中的 FFmpeg，否则使用 imageio-ffmpeg 自带程序。

需要提供 `MIE_LOOP_CTX` v3 的 MieLoop 插件。该上下文至少含 `version=3`、24 位小写十六进制 `run_id`、从 0 开始的 `index`、正整数 `count`。本仓库不包含循环节点。

需要包含 `MiniMaxH3ReferenceToVideo`、`MiniMaxH3AddGuide` 及 `comfy.nested_tensor.NestedTensor` 的 ComfyUI 版本，并单独安装配置 H3 模型、文本编码器、视频 VAE、音频 VAE 与采样节点。模型权重不包含在本仓库。

多参考图节点接受外部上传节点输出的 `IMAGE_LIST`：`{"items": [{"path": "本地图片绝对路径"}, ...]}`，需 1–9 张，不接受普通 IMAGE 批次；逐张独立加载，保留顺序。

可通过环境变量 `H3_FFMPEG` 指定 FFmpeg 可执行文件的完整路径。

节点所属插件分类、节点标题、参数名称、输入输出名称、提示说明及下拉选项均提供中英文。跟随 ComfyUI 设置中的 `Comfy > Locale > Language`（`Comfy.Locale`）显示；`zh` 为简体中文，其余未提供的语言回退英文。

翻译使用 ComfyUI 原生 `locales/en` 与 `locales/zh`；前端扩展在语言切换时同步更新已存在的画布节点。自定义标题会保留。需使用支持 `/api/i18n` 的 ComfyUI；旧前端若未刷新节点搜索菜单，请刷新页面。GitHub 仓库名和安装文件夹名固定，不随语言更改。

保留原始节点 ID、端口内部标识、输入顺序、默认值与输出目录，以兼容已有工作流。采样步数节点的 `总步数`、`一采步数` 内部标识仍保留，显示名称由语言决定。

迁移时仅安装新文件夹，移走旧 `h3_av_sync`，避免重复注册同一节点。

## 典型连接方式

1. MieLoop v3 的 `loop_ctx` 连接分段计划；向 `prompts` 提供全部分段脚本，`seconds` 通过外部数值节点连接。可选地将列表分割器接入提示词选择节点，再接计划的 `segment_prompt` 进行一致性检查。
2. 将计划的 `prompt`、`window_frames`、`previous_frames`、`previous_audio`、`speaker_reference` 接入多参考图条件编码的对应端口，`window_frames` 接 `length`；连接 H3 CLIP、参考图列表及相应 VAE。首段的续写与音色输出为空。
3. 使用原生 H3 联合采样器；需要原生锚定时，先通过续写锚定节点处理正向条件。若二采仅精修画面，先锁定音频，二采后恢复一采音频，再进行视频与音频解码。
4. 解码画面和音频接入同步保存节点；计划的 `window_frames` 接 `expected_frames`，`skip_frames` 接同名输入，上下文帧数保持一致。将保存节点返回的 `loop_ctx` 接回 MieLoop，确保当前段提交后才推进下一段。
5. 循环完成后，将最终 `loop_ctx` 及完成标记 `done` 接入成片合成节点。

## 节点及参数

### H3 分段生成计划

`H3AVSegmentPlan`

规划 24 fps H3 生成窗口、脚本时序、确定性种子及成对的音画续写上下文。

| 输入（内部标识） | 显示名称 | 类型 / 默认值 | 用途 |
| --- | --- | --- | --- |
| `loop_ctx` | 循环上下文 | MIE_LOOP_CTX | 连接 MieLoop v3 的循环上下文，用于识别本次运行及当前分段序号。 |
| `prompts` | 全部分段脚本 | STRING / 须连接 | 一个 STRING，使用 ----------SEGMENT_SEPARATOR---------- 分隔，每个循环段对应一份非空脚本。 |
| `seconds` | 本段新增时长（秒） | FLOAT / 须连接 | 本段新增内容的目标时长；实际时长按 24 fps 对齐至 H3 支持的帧数窗口。 |
| `overlap_frames` | 续写上下文帧数 | INT / `22` | 上一段承接音画的帧数，必须为 17k+5，如 5、22、39；计划与写出节点须保持一致。 |
| `base_seed` | 基础种子 | INT / `1087183784971949` | 每段种子为（基础种子 + 从 0 开始的段序号）对 2^64 取模。 |
| `segment_prompt` | 当前分段脚本 | STRING / 可选 / 须连接 | 当前段的原始脚本；若接入计划节点，必须与该循环序号对应的脚本一致。 |

| 输出序号 | 显示名称 | 类型 | 含义 |
| --- | --- | --- | --- |
| 0 | 生成提示词 | `STRING` | 文本条件提示词；计划节点会加入时序、音画联合生成及续写指令。 |
| 1 | 生成窗口帧数 | `INT` | 本段总生成帧数；从第二段起包含续写上下文。 |
| 2 | 上一段画面上下文 | `IMAGE` | 上一段末尾的上下文画面；首段为空。 |
| 3 | 上一段音频上下文 | `AUDIO` | 与上一段画面上下文严格对齐的音频；首段为空。 |
| 4 | 需去除的重复上下文帧数 | `INT` | 首段为 0，后续段等于上下文帧数；写出时同时去除对应音频区间。 |
| 5 | 本段种子 | `INT` | 由基础种子与当前从 0 开始的段序号计算出的确定性种子。 |
| 6 | 说话人音色参考 | `AUDIO` | 首段音频的前至多 3 秒，用于后续段的说话人身份及音色参考。 |

### H3 同步裁剪并保存分段

`H3AVEncodeSegment`

同时去除重复音画上下文，保存 H.264 画面、精确长度 PCM 音轨及下一段续写所需末尾上下文。

| 输入（内部标识） | 显示名称 | 类型 / 默认值 | 用途 |
| --- | --- | --- | --- |
| `loop_ctx` | 循环上下文 | MIE_LOOP_CTX | 连接 MieLoop v3 的循环上下文，用于识别本次运行及当前分段序号。 |
| `images` | 视频帧 | IMAGE | 解码后的 RGB IMAGE 批次，形状为 [帧数, 高, 宽, 3]；H.264 要求宽高为偶数。 |
| `audio` | 本段音频 | AUDIO | 与画面同段的解码 AUDIO，含 [1, 声道, 采样点] waveform 和正数 sample_rate。 |
| `expected_frames` | 计划窗口帧数 | INT / 须连接 | 连接计划节点的 window_frames 输出；解码帧数必须完全匹配。 |
| `skip_frames` | 需去除的重复上下文帧数 | INT / 须连接 | 首段为 0，后续段等于上下文帧数；写出时同时去除对应音频区间。 |
| `overlap_frames` | 续写上下文帧数 | INT / `22` | 上一段承接音画的帧数，必须为 17k+5，如 5、22、39；计划与写出节点须保持一致。 |
| `crf` | H.264 质量（CRF） | INT / `19` | 恒定质量系数，范围 0–51；数值越小质量越高、文件越大，默认 19。 |
| `preset` | H.264 编码速度预设 | medium/fast/veryfast/slow | medium 为均衡；fast/veryfast 缩短编码时间；slow 在相同 CRF 下花更多时间改善压缩。 |
| `reject_silence` | 拒绝近乎静音的音频 | BOOLEAN / `true` | RMS 低于 -65 dBFS 时拒绝写出该段并保留原始音频诊断；静音场景可主动关闭。 |
| `continuation_images` | 供下一段续写的参考画面 | IMAGE / 可选 | 可选上下文来源，须与输出帧数一致；适合输出二采画面时保留一采画面用于续写。 |
| `create_av_preview` | 生成含音频的分段预览 | BOOLEAN / `false` / 可选 | 额外生成含 AAC 音频的分段预览 MP4；最终成片仍使用 PCM 主音轨。 |

| 输出序号 | 显示名称 | 类型 | 含义 |
| --- | --- | --- | --- |
| 0 | 循环上下文 | `MIE_LOOP_CTX` | 连接 MieLoop v3 的循环上下文，用于识别本次运行及当前分段序号。 |
| 1 | 仅含画面的分段路径 | `STRING` | 仅含画面的分段主文件绝对路径；配对的 PCM 音轨另存于 WAV。 |
| 2 | 分段诊断（JSON） | `STRING` | JSON 诊断，包含帧数、源音频时长偏差、输出采样点、峰值、RMS 及削波比例。 |

### H3 多参考图视频条件编码

`H3AVReferenceListToVideo`

读取 IMAGE_LIST 中的 1–9 个图片路径，作为独立的原生 H3 参考图编码，可附加视频与音色上下文。

| 输入（内部标识） | 显示名称 | 类型 / 默认值 | 用途 |
| --- | --- | --- | --- |
| `clip` | H3 文本编码器 | CLIP | 供原生 H3 文本与参考编码使用的 CLIP 对象。 |
| `images` | 参考图片列表 | IMAGE_LIST | IMAGE_LIST 字典，其 items 是包含 1–9 个对象的列表，每个对象含有效的本地图片 path；不是 IMAGE 张量批次。 |
| `prompt` | 生成提示词 | STRING / 须连接 | 文本条件提示词；计划节点会加入时序、音画联合生成及续写指令。 |
| `width` | 视频宽度 | INT / `1344` | 目标视频宽度，单位为像素；此参考编码节点按 32 的倍数设置。 |
| `height` | 视频高度 | INT / `768` | 目标视频高度，单位为像素；此参考编码节点按 32 的倍数设置。 |
| `length` | 生成窗口帧数 | INT / `124` | 总生成帧数，单位不是秒；分段续写时连接计划节点的 window_frames 输出。 |
| `ref_image_size` | 参考图尺寸策略 | match/max / `match` | match 按目标尺寸适配；max 使用原生 H3 编码器的最大参考尺寸策略。 |
| `vae` | 视频 VAE | VAE / 可选 | H3 原生视频编码器/解码器，用于视频引导或参考图像。 |
| `audio_vae` | 音频 VAE | VAE / 可选 | H3 原生音频编码器/解码器，用于音频引导或参考。 |
| `previous_frames` | 上一段画面上下文 | IMAGE / 可选 | 上一段末尾的上下文画面；首段为空。 |
| `previous_audio` | 上一段音频上下文 | AUDIO / 可选 | 与上一段画面上下文严格对齐的音频；首段为空。 |
| `speaker_reference` | 说话人音色参考 | AUDIO / 可选 | 首段音频的前至多 3 秒，用于后续段的说话人身份及音色参考。 |

| 输出序号 | 显示名称 | 类型 | 含义 |
| --- | --- | --- | --- |
| 0 | 正向条件 | `CONDITIONING` | H3 正向条件；续写锚定节点从第二段起在第 0 帧加入配对的音画上下文。 |
| 1 | 初始音画潜空间 | `LATENT` | 参考编码器返回的 H3 原生音画联合初始潜空间。 |

## 文件与故障排查

输出目录：`ComfyUI/output/h3_av_sync/<run_id>/`，兼容原插件路径。

- `manifest.json`：按提交顺序记录分段；`final.mp4`：最终成片；`*.log`：FFmpeg 日志。
- 至少预留 2 GiB 空闲磁盘空间。合成时还需大于分段总大小加 1 GiB 的剩余空间。磁盘不足时已完成分段保留。
- 发生覆盖、清单或段序号错误时，检查连接并使用新的循环 run_id；不要删除清单后继续沿用旧分段。分段必须按顺序执行，不能并行写同一 run_id。

`segment_*.mp4` 是仅含画面的主文件，配对 `segment_*.wav` 是 48 kHz 双声道 PCM 音轨；`tail_*.npz` 存续写上下文，通常仅保留最新一段；`speaker_reference.npz` 存首段音色参考；`plan_*.json` 与 `prompt_*.txt` 存计划与实际提示词；`final_info.json` 存成片帧数与音轨信息。启用预览后额外生成 `preview_*.mp4`。

源音频与画面时长偏差超过 0.05 秒会报错；不会使用静音掩盖明显错配，也不做音频时间拉伸。允许范围内的短尾差异会按帧边界补齐或裁剪并记录诊断。静音拒绝会保存 `rejected_*.f32le` 和对应 JSON。计划生成的指令目前面向中文口播，切换界面语言不会改写生成内容。
